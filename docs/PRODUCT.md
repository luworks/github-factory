# Moonshot product definition

## Thesis

Open source already has worlds: interfaces people enter, engines doing the work, packages connecting teams, infrastructure shipping changes. The repository file browser flattens these places into paths; dashboards split their progress into separate tools. Moonshot makes a navigable mental model of the whole project and keeps the work attached to its source.

The winning demonstration is not a fictional factory that happens to have GitHub counters. It is the same unfamiliar, real repository becoming understandable in sixty seconds: paste a URL, discover the districts, inspect a source-backed connection, see a real change, and find an informed next contribution. Switching to a second, unrelated repo proves the system generalizes. Switching styles proves the world model is separate from its presentation.

## Audiences and jobs

1. A new contributor asks where a feature lives and what to tackle next.
2. A maintainer asks which work and CI need attention in the context of their architecture.
3. A curious developer wants to understand a prominent project without reading hundreds of folders.

The first version is public and read-only. It does not compete with GitHub's write workflows or claim to monitor runtime services.

## Core loop

1. Choose a curated world or paste a public GitHub repo.
2. Survey paths, dependency manifests, issues, PRs, commits and workflow runs.
3. Explore an architecture map whose districts have stable identities and evidence links.
4. Open the field guide for grounded explanations and suggested next moves.
5. Revisit to see observed project activity; source changes refresh independently from paid AI analysis.

The game layer rewards comprehension. Buildings, paths, districts, connected work and exploration provide spatial memory and discovery. It does not invent performance scores, developer rankings or measurable throughput from animation.

## Experience

The landing page uses an editorial, warm mission-control aesthetic: a direct repository input, an original lunar world, and six curated projects. The explorer dedicates most space to the interactive world, with an accessible district index, a source inspector and tabs for real activity and the AI field guide. Five perspectives are immediately switchable. English is the competition default, Chinese remains available.

Statuses are bounded: a green workflow conclusion is green, an active workflow is active, skips and missing evidence are distinct. Architecture inference has a visible badge. A cached timestamp is visible, and collection failures preserve the last useful world with a clear signal problem.

## Generation architecture

The generated product is a typed world blueprint rendered by trusted components. The AI maps the specific public repository into domain descriptions and evidence-linked recommendations. It does not ship arbitrary generated JavaScript or allow README instructions to become privileged prompts. A future richer theme generator can extend the schema without surrendering this execution boundary.

## Scope for the five-hour build

Must have: independent TanStack Start app; real public GitHub ingestion; persistent cache; strict shared model; five recognizable visual styles; interactive district inspection; real work/CI activity; bounded Muse runtime; curated pre-generated repos; source identity, timestamps and coverage; accessible narrow-screen experience; browser acceptance and exact spend report.

Later: authenticated private repositories with explicit consent; webhook updates; richer code-level dependency analysis; permissioned actions; save/share custom blueprints; measured contributor onboarding benefit. These are roadmap ideas, not delivered features.

## Judging narrative

Creativity: an explorable world, not another dashboard. Technical ambition: arbitrary repository analysis and a provider-independent world schema. Working proof: two unrelated public repositories, source-linked inspection, actual GitHub activity, and a successful Muse generation. Reliability: bounded ingestion, no code execution, clear evidence levels, persisted spending guard and graceful degraded operation.

Track, portal artifacts, demo-duration rules and submission details remain subject to the participant portal. The project is not described as submitted or qualified by this document.
