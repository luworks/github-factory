# Deployment

Target: `https://chaorders.com/github-factory`.

## Bun application

The app needs Bun 1.4.4, a persistent SQLite directory and a single active serving instance per mounted data directory. Default path is `/github-factory/` and default local port is 4177. Create a private `.env` from the example and leave the paid budget at zero unless paid use is authorized. Keep data and ledger across releases. Never fork an active paid ledger or point a second model-enabled deployment at a fresh budget.

```sh
bun --no-env-file install --frozen-lockfile --ignore-scripts
MOONSHOT_BASE_PATH=/github-factory/ bun run build
HOST=127.0.0.1 PORT=4177 bun run start
curl --fail http://127.0.0.1:4177/github-factory/api/health
```

After committing a validated candidate, `MOONSHOT_SKIP_BUILD=1 scripts/install-local.sh` installs a versioned independent user service. It does not modify the incumbent `moonshot-web` service. Configure an **absolute** `MOONSHOT_DATA_DIR` in the private `.env` before service installation so release changes preserve the same cache and ledger. Inspect with `systemctl --user status github-factory-web`. The service records its exact source SHA.

Alternatively, `docker compose up --build -d` runs the Bun image on loopback with a persistent volume. Copy `.env.example` first; Docker reads `.env` server-side and never builds it into the image. Host filesystem paths in `MOONSHOT_DATA_DIR` are overridden by `/app/.data` inside the container. For rollback use the prior image/source with the **same** data volume and matching path; never delete the volume to reset spending.

## Existing Cloudflare site

The company site uses Cloudflare Workers. Bun SQLite cannot run inside that existing Worker. Deploy the Bun app on an authorized persistent host, expose an HTTPS origin through an authorized gateway/tunnel, then route only `/github-factory` and `/github-factory/*` to it. Keep the path prefix intact. Preserve the browser's original Host/Origin at the trusted reverse proxy, or validate an exact configured public origin server-side before allowing writes. Do not trust arbitrary forwarded headers.

`deploy/nginx-location.conf` is an example for a trusted same-host reverse proxy. The snippet preserves the Host and uses a 190-second proxy timeout to accommodate bounded repository collection and generation. Existing domain/Worker routing still needs to send this prefix to that proxy; copying the snippet does not make the domain live.

## Acceptance before claiming public deployment

- The exact repo head passes CI and its installed source SHA matches health.
- Public landing page, direct world deep link, scripts/CSS/favicon and prefixed APIs return usable responses.
- Pasting a public repo, changing perspective, source inspection and refreshing work on the public origin.
- Failed/partial/stale collection stays visible; any optional paid provider has a separately recorded real acceptance and ledger delta.
- Existing company paths still work and the origin is reachable with the intended access boundary.

Local checks are distinct from public DNS, gateway configuration, production rollout and live provider acceptance. No production-origin route or DNS change is performed by the setup scripts.

## Independent Cloudflare path gateway

`deploy/gateway.ts` is an independent Worker forwarding to `FACTORY_ORIGIN`, an HTTPS tunnel origin backed by the persistent Bun host. Build it with `bun build deploy/gateway.ts --target=browser --outfile=/tmp/github-factory-gateway.mjs`. Deploy it separately from the company-site Worker with the zone route `chaorders.com/github-factory*` and a `COMPANY_SITE` service binding to the existing `chaorders-site` Worker. Cloudflare matches query strings as part of its route selection: two exact path routes miss `/github-factory?style=...`. The gateway handles only the exact product path and its slash-prefixed children; adjacent paths such as `/github-factory-other` pass the original request and response through the company binding. The bare product path redirects to its trailing slash and retains the query string. No company-site source is bundled or modified.

Create a dedicated named tunnel and connector for this app; do not repurpose an existing shared connector. Its ingress must preserve `/github-factory/`, forward to loopback port 4177, and reject other paths. The app's server-only environment must set `MOONSHOT_PUBLIC_ORIGIN=https://chaorders.com`. The gateway retains that browser Origin, removes caller-supplied Host/forwarded headers, cookies and Authorization, and uses the tunnel's own HTTPS host upstream. Cross-origin POSTs are rejected at both layers. Never forward or expose the model keys through the Worker.

Rollback the public cutover by removing only the recorded product route; the existing company-site Worker remains deployed. To roll back the Bun app, restore the previous `github-factory-web.service` unit and restart that service, retaining the same absolute data directory. Preserve all SQLite files and paid ledger history. Keep the prior release and gateway/tunnel identities in a private deployment record. A rollback of a failed first cutover restores the pre-existing product 404; it does not create a previous public product release.

## GitHub Actions configuration

The repository uses `CLOUDFLARE_API_TOKEN` as an Actions Secret. Required permissions are target-account Workers Scripts Edit and Cloudflare Tunnel Edit, and `chaorders.com` Zone Read, DNS Edit and Workers Routes Edit. Never print it or put it in Variables, application `.env`, client bundles or build arguments.

Non-secret repository Variables are `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_ZONE_ID`, `FACTORY_ORIGIN`, `MOONSHOT_BASE_PATH`, `MOONSHOT_PUBLIC_ORIGIN`, `MOONSHOT_GITHUB_REQUESTS_PER_HOUR` and `MOONSHOT_BUDGET_USD` (zero). `FACTORY_ORIGIN` points to the dedicated HTTPS tunnel hostname. These Variables are configuration records: storing them does not itself deploy a Worker or change the persistent host environment. The current app host is deployed separately with `scripts/install-local.sh`; existing CI performs checks and synthetic tests only. No model credentials or connector token belong in the frontend build.

## Public collection and model limits

`MOONSHOT_GITHUB_REQUESTS_PER_HOUR` defaults to **45 upstream HTTP attempts per UTC hour**, deployment-wide, persisted in `public-quota.sqlite` in the data directory. Retries count; cached reads do not. Admission is atomic across SQLite connections and survives service restarts. Zero disables collection. This is independent of the paid model ledger and does not imply that GitHub grants this many requests: unauthenticated limits can also be shared by other applications on the host. Upstream 403/429 and partial collection remain visible. At most two collections run concurrently; fresh data is cached for 90 seconds and forced refresh has a 15-second minimum interval. Public mutations also retain their shared eight-per-minute operation limit. An exhausted allowance leaves previous source evidence visible as stale; it is not reported as fresh success.

Importing a repository, refreshing facts and changing styles do not request a new paid guide from the browser. AI generation has its own explicit action, disabled when the provider is unconfigured or no budget remains. Production must retain zero budget and empty model credentials until separately authorized; no historical paid ledger is moved, copied or reset by this cutover.


## Public analysis security and Meta spending

The public UI is branded **Moon Factory**; legacy `MOONSHOT_` configuration names and the `/github-factory/` URL remain stable. Public analysis accepts only an HTTPS `github.com/owner/repo` root URL and its explicit analysis action. Extra prompt/code/provider/model fields are rejected. Any publicly accessible GitHub repository is eligible. License metadata (including null/NOASSERTION/custom) is displayed as reported and never blocks analysis. The editorial catalog currently contains nineteen entries; a policy change does not silently expand it. Historical cached maps are labeled stale and do not imply current visibility/head revalidation. The UI is English only; old Chinese preferences are ignored without translating original GitHub content.

The Worker must contain a private `FACTORY_GATEWAY_SECRET` Secret matching the server-only `MOONSHOT_GATEWAY_SECRET` (at least32characters). It overwrites client identity headers using Cloudflare's ingress address. Source collection/AI APIs reject direct-origin calls without that secret. Do not place it in Variables or client code. Cache-only gallery previews authenticate the gateway but perform no collection or model calls and do not consume expensive-action quotas.

Persistent defaults are10sensitive requests/IP/minute,6new collections/IP/hour,2AI actions/IP/hour and6AI actions/deployment/hour, independently of the upstream HTTP-attempt allowance. Raw IPs are not stored; keyed HMAC identities are kept in the separate public-access SQLite file. Pending and failed admissions are not erased on restart. Rotating IPs cannot evade the deployment-wide AI guard or the shared monetary ledger.

Public provider/model/endpoint are fixed to Meta Muse Spark1.3 at `https://api.meta.ai/v1`. To activate paid use, an explicitly authorized existing absolute `MOONSHOT_BUDGET_LEDGER_PATH` is mandatory; a new checkout remains keyless with zero budget. The cumulative original ledger cap remainsUS$50. Public `MOONSHOT_HOURLY_BUDGET_USD` is hard-clamped toUS$0.30 per rolling60minutes, using a declared conservative accounting ceiling10CNY/USD (=CNY3), not a market exchange-rate claim. Reservation admission checks cumulative and hourly totals in the same SQLite immediate transaction, includes all pending reservations and failed charges, and records public settlement times in an additive table in the SAME physical ledger. Never copy or initialize another paid ledger.

The protected incumbent service is not restarted and does not implement this new hourly admission rule. New public admissions consider shared-ledger cost, while legacy settlements lacking a recorded settlement timestamp use their call-start timestamp. Therefore the new public runtime's bound must not be presented as an unconditional combined-service billing guarantee. A read-only monitor should retain this boundary and inspect all shared-ledger charges, failures and reservations. Real provider validation is separate from configuration and requires an explicitly authorized bounded analysis; tests and CI never call paid APIs.


## Authoritative D1 world storage

`MOONSHOT_WORLD_STORE=d1` switches **only public GitHub world snapshots and canonical aliases** to Cloudflare D1. The default remains `sqlite` for keyless local development. The Bun host, original model ledger, cached model guides, IP admission database and upstream-attempt database remain in place. No paid ledger, model credential, raw IP or Cloudflare management token enters D1 or the gateway Worker. D1 is storage, not a replacement Bun runtime.

Apply `deploy/d1/0001-world-cache.sql` and `0002-migration-identity.sql`, recording each SQL SHA256 and migration time. Storage schema version is **2**; `WorldSnapshot.schemaVersion` remains **1**. Initialize the dedicated database's `storage_identity` with its actual UUID and a random binding nonce. The Worker `WORLDS_DB` binding, configured UUID and stored UUID must agree. Configure a distinct storage Secret and server-only bridge URL/key plus `MOONSHOT_D1_DATABASE_ID`. No account management token enters application config or the Worker.

`migrationImport` is a fixed authenticated RPC, requires an active edge admission fence and matching candidate/epoch/database identity, accepts at most2MiB and validates the complete export before writing. One documented [Worker D1.batch transaction](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch) writes the empty-target guard, **all worlds**, **all aliases** and provenance. Admission requires worlds, aliases, provenance **and migration_guards** to be empty in that same transaction; exact completed own-migration retries remain idempotent. A failed statement rolls back the whole sequence; REST query-array atomicity is not assumed. Exact completed imports are idempotent; unrecorded non-empty destinations are rejected without deleting or overwriting their rows. A duplicate-statement sentinel probe separately proves real D1.batch rollback without touching business rows.

The async adapter coalesces up to32concurrent world keys; gallery summaries use one batch and require valid source/head/capture/tree/nodes before enabling navigation. D1 errors, identity mismatch, timeout or malformed results return503 `WORLD_STORAGE_UNAVAILABLE`, never a fabricated miss or SQLite fallback. Health queries the actual selected database/schema and reports new-app HOLD/activity. A cache hit, including expired evidence, never starts collection; a true miss or explicit refresh may collect subject to unchanged limits.

The first restart needs a retirement fence because the legacy9b app has no HOLD/activity counters. Deploy the reviewed edge admission fence before stopping anything: world GET/HEAD, create/refresh/AI and unknown API admissions return503; cheap GET/HEAD gallery/preview/health/budget can continue initially. Before any connector interruption, independently read Cloudflare management evidence for the physical database binding, one 100% active deployment/version, the actual deployed module bytes, and all fence/origin/company/source/epoch settings. The private drain config must pin `workerAuthority.deploymentId`, `versionId` and `moduleSha256`; authenticated RPC status alone cannot authorize interruption. Then stop **only the dedicated product connector**, after checking its exact unit/token/tunnel identity and single-product ingress. Verify that Cloudflare reports no tunnel connections and the retiring Bun PID has no accepted input sockets. This closes previously accepted slow request bodies and prevents old origin requests from reentering after the fence. Keep the retiring Bun alive.

The reviewed `scripts/drain-retiring-runtime.ts` waits at least240seconds after input closure (60second source collection + bounded model fetch/body up to90seconds + settlement/transport margin). It checks the same PID/start time/boot ID, original ledger device/inode and protected old PID, then requires30continuous seconds with no active/unknown process sockets and no public `ai_public_hourly` reservations or new public admission. IPv4/IPv6 TCP/UDP/raw and UNIX sockets are classified; only the exact inherited journald UNIX stream can be ignored. A sampling gap above5seconds resets the quiet window. Legacy reservations are recorded separately and never cancelled/settled. Unknown or remaining work fails closed. The ledger authority comes from a separately pinned original handoff receipt, never from the current environment: absolute path, realpath, device and inode must all agree in retirement, selection, opening and rollback gates. A current environment pointing to a copied ledger cannot establish its own authority. Repeat the independent management checks throughout draining, at the final retirement boundary and immediately before restart. Each observation brackets the actual module read with current deployment/settings readbacks; unknown or changed traffic, bindings, version or module aborts. A final fresh receipt check immediately precedes the restart. No new-process zero counter or instant zero reservation is accepted as retirement proof.

Install the same tested artifact on the **new product service only**, initially using SQLite with HOLD already set. The connector can reopen under the still-active edge fence after exact candidate/held health is verified. The protected old service/port4176 and all existing ledger/admission files remain unchanged. This procedure deliberately has a maintenance window; record its actual start/end, response gaps and available read scope.

Export all source worlds/aliases in one read-only SQLite transaction. Preserve raw serialized snapshot SHA256, canonical identity, source head/capture and absolute expiry/saved times. Migration does not extend TTL or claim fresh upstream verification. After the atomic import, `migrationSnapshot` returns one consistent full RPC readback. Before **selection, HOLD release and edge-fence release**, machine gates freshly compare every row/alias/hash/expiry plus provenance/guard through both management API and RPC. Each gate and its consumption independently reread the actual deployed module and current single-100%-version deployment/settings: the physical `WORLDS_DB.id`, storage mode, exact fence string, origin/company binding, source SHA, epoch and bundle hash must match. Copied database rows/identity cannot stand in for that physical binding. They bind actual deployment ID, version ID, database UUID+nonce, migration export digest, candidate SHA, freshly read deployed Worker module hash, active environment hash, target config hash and one random epoch. Old/missing receipts, a schema-compatible empty/wrong binding or any tampering reject the transition. Receipts expire in30seconds and configuration is rechecked before use. `scripts/d1-migration-gate.ts` contains the testable comparison/receipt contract.

Restart the new app with D1 selected and HOLD still on, verify real backend reads, then pass the full gates before reopening. Follow sentinel rollback proof with a normal GitHub-only refresh and exact D1 runtime snapshot readback; no model spend is needed. Real public acceptance, synthetic browser coverage, storage probes and historical Meta acceptance must be reported separately. Verify the unchanged original ledger identity/cumulative history without copying it.

Rollback is explicit; there is no automatic fallback. Retain the previous release, unit, private environment and original local world database. After D1 has accepted runtime writes, first HOLD and drain the new service; export and compare the D1 delta and backfill public snapshots/aliases into the retained SQLite world database before selecting SQLite, so rollback does not silently lose new public captures. If D1 is unreachable, preserve that delta as UNKNOWN and use a clearly stale retained cache only under an explicitly recorded rollback decision. The model ledger and both admission authorities never change during forward or rollback migration. Do not delete either backend or any historical paid data.


Bridge-only permissions are one-attempt permissions. They bind an expiring grant, unique attempt ID, initial and deployed Worker versions, frozen helpers/artifacts, legacy SQLite runtime and unchanged financial authority. An execution is consumed before mutation; rollback is permitted only for that exact still-active probe-only version with no business migration. A completed rollback permanently revokes it. Starting a full cutover transfers authority and revokes every old bridge rollback path; an old bridge grant cannot bypass HOLD, drain or D1 delta reconciliation after runtime writes. Recovery from an unknown state requires a separately reviewed recovery decision.
